1. "Is there a best use multi model?" — Multi-Model Routing

Short answer: Yes, and OrcaRouter has the strongest implementation in market.

Fusion (Fable 5-level replacement)

Call a curated panel of frontier models behind one slug. They answer in parallel, and a judge returns the single strongest answer cross-checked against the rest.

"Fable 5 is gone. This is the answer you can call today."
OpenAI-compatible, no waitlist.

How Fusion works:

  • You call a single model slug (e.g., orcarouter/fusion)
  • OrcaRouter fans out to N frontier models in parallel
  • Each model answers independently
  • A judge model evaluates all answers, cross-checks them, and returns the single strongest verbatim
  • Not a black-box blend — you get one model's actual output, just the best one

Fusion billing: You pay for each model leg + the judge. Parallel fan-out means N× token cost per call. Transparent in the usage object.

Other routing strategies:

  • Auto Router (orcarouter/auto): Cheapest live model per request
  • Model Fallbacks: Chain via extra_body.models — if primary 5xx/429, next serves transparently
  • Named Routers: Save strategies, invoke by name
  • Routing DSL: YAML + CEL programmable routing with shadow/canary rollout

Versus OpenRouter: OpenRouter has model fallback. It does not have Fusion (parallel panel + judge), Named Routers, or a programmable routing DSL.

2. Guardrails & Limitations — "Per Person" AI Governance

Short answer: Yes. OrcaRouter has a workspace-scoped guardrail engine + agent firewall that bind per-API-key, giving per-person/per-team controls.

Guardrails (Content Policy Engine)

  • Attach once, every bound key screened on next call — no redeploy, no SDK change
  • Input-stage: Block/mask/flag PII, secrets, prompt injection, sensitive words, brand-unsafe content
  • Output-stage: Screen model responses for same categories
  • PII Shield: One-click redaction (SSN, credit cards, emails, phones, addresses). Custom PII entities supported.
  • Prompt injection detection: Direct + indirect injection protection
  • Code security: Regex-based dangerous pattern detection
  • Cost guardrails: Cap spend per key/workspace
  • Stream-safe: All rules work on streaming responses

Agent Firewall (Tool Governance)

  • 4 stages: Inbound, Response, MCP, Egress
  • 6 verdicts: Allow, Audit, Deny, Sanitize, Pending Approval, Cap Cost
  • Tool allow-listing: Default-deny with glob patterns
  • Argument validation: JSONPath clauses (eq, contains, regex, in, cidr_match)
  • Egress control: Host/CIDR allow/deny for SSRF prevention
  • Human approvals: pending_approval verdict + webhook with HMAC signing
  • Cost circuit breaker: Per-run spend limits
  • Sequence rules: Detect attack chains static rules miss
  • Shadow mode: Dry-run against live traffic before enforcing

MCP Security (subset of Firewall)

  • Register MCP servers behind single audited gateway
  • Every tools/call firewall-evaluated before execution
  • SSRF protection, encrypted credentials
  • Rug-pull defense: detect when MCP server behavior changes
  • Schema-drift detection

Firewall: Skills

Scan and risk-score agent capabilities (skills, MCP servers, plugins) before they run. Deterministic scanner assigns risk band + enforcement mode.

Per-Person Controls (Scoped API Keys)

  • Unlimited scoped keys, each bound to specific policies
  • Model limits: Restrict which models a key can access (Intern → GPT-4o-mini, Senior → Claude Opus)
  • IP allow-list: Lock keys to specific IPs/VPNs
  • Quotas, caps, expiry: Per-key rate limits, token caps, auto-expiring keys
  • Environments: Tag keys as production/staging/testing with different policies

Versus OpenRouter: OpenRouter has rate limits and model access control. It does not have a guardrail content engine, agent firewall, MCP security, or skills scanner. If Colin wants to control "what each person can do" — OrcaRouter wins decisively.

Data Handling & Zero Retention (Key Differentiator)

Zero Data Retention is the DEFAULT — not a per-request opt-in, not a checkbox. Every request, every response, every time.

What OrcaRouter NEVER stores:

  • Prompt content, messages, tool call payloads
  • Model outputs (text, images, TTS audio)
  • Uploaded audio, images, files
  • Tool call arguments or results
  • Full error payloads (only truncated error messages for debugging)

What IS stored (metadata only):

  • Timestamp, API key identifier (not secret), model requested
  • Token counts, latency, HTTP status code, cost
  • Whether model was resolved from a router
  • This is for billing, security, and debugging

Privacy commitment: "We never sell your data."

Caveat: Upstream providers (OpenAI, Anthropic, etc.) still receive your data. OrcaRouter's zero-retention applies to the gateway layer. Provider data policies apply downstream.

🔒 Massive Differentiator vs OpenRouter
OpenRouter does not document their data retention policy publicly. Zero-retention-as-default is a major trust signal for enterprise buyers.
