Why They Need OrcaRouter — The 3 Angles

🎯

Angle 1: MCP Server → They're Already Our Customer Archetype

Their architecture is the exact problem OrcaRouter solves.

Shopware just launched an MCP Server — Anthropic's Model Context Protocol — that connects their platform to ChatGPT, Claude, Cursor, Codex, and any MCP-compatible client. They explicitly said: "none of this is tied to a specific model provider… switching providers doesn't require changes."

That's OrcaRouter's exact value proposition — one layer below. Their MCP Server abstracts which AI client connects. OrcaRouter abstracts which model serves the request. These stack perfectly — their MCP Server calls our API, and we handle routing, failover, cost optimization, and security across 200+ models.

The Pitch

"You built an MCP Server so merchants can use any AI client. But every one of those clients is still calling one model at a time — and you're managing multiple API keys, rate limits, failover logic, and security per provider. OrcaRouter sits behind your MCP Server. One endpoint. Automatic failover. 30-50% cost savings via model routing. And a security firewall that inspects every tool call your Copilot makes."

🔐

Angle 2: Copilot Tool-Calling = Security Time Bomb

Agentic actions into live e-commerce — prompt injection is inevitable.

Shopware's Copilot executes agentic actions: order management, inventory updates, customer data. That means it's making tool calls into a live e-commerce platform. One prompt injection → read customer PII, modify orders, exfiltrate merchant data through the MCP Server. Their blog says Copilot is "permission-aware, secure-by-design" — but LLM-level guardrails aren't enough. You need a gateway-level firewall.
The Pitch

"Your Copilot has access to merchant stores — orders, customers, inventory. What happens when a prompt injection tricks it into exfiltrating data through a tool call? OrcaRouter's firewall sits between the LLM and your infrastructure — allow/deny/sanitize every tool call, require human approval for write operations, full audit trail. It's the compliance layer your MCP Server is missing."

🔗

Angle 3: The LangFuse Connection — Complement, Not Competitor

They already use observability — that's an on-ramp, not a roadblock.

Shopware already uses LangFuse (Berlin-based, open-source LLM observability) for tracing and evaluations. They published a whole blog post about it. This is actually a selling point for OrcaRouter, not a blocker. LangFuse watches what happens. OrcaRouter controls what happens. They're complementary — LangFuse traces the requests; OrcaRouter routes them to the right model and blocks the dangerous ones.
The Pitch

"We use and recommend LangFuse too — it's great for observability. But observability tells you what happened after the fact. OrcaRouter prevents it before it happens. Routing + firewall + guardrails at the gateway layer, with LangFuse tracing on top. That's the complete stack."
